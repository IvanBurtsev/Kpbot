# Состояние проекта kpbot

**Дата:** 25 ноября 2026
**Версия в работе:** ветка `main`, последний коммит — см. `git log -1`
**Тестов:** 214, все зелёные

---

## 1. Коротко

Сервис превращает письмо с заявкой в коммерческое предложение: разбирает позиции,
сопоставляет с прайсом, считает НДС, готовит PDF/DOCX/Excel, отправляет клиенту и
уведомляет менеджера в Telegram и MAX.

**Продукт функционально закрыт для одного пилота.** Не готов к продаже без:
переезда сервера в РФ, документов по персональным данным и одного живого клиента.

## 3. Что работает, но проверено на демонстрационных данных

Эти вещи работают, но **не на реальных данных клиента** — при показе это надо
проговаривать честно.

| Возможность | На чём проверено |
|---|---|
| Демо-заявки (6 штук) | сгенерированы из прайса, не настоящие письма |
| Остатки в заявке (55 позиций) | загружены вручную, не из 1С |
| Самообучение на правках | тесты и ручной прогон, боевого накопления пока нет |

## 4. 1С: что реально сделано

| Действие | Статус |
|---|---|
| Клиент OData, чтение справочников и документов | ✅ работает на живой базе |
| Авторизация, отдельный пользователь для API | ✅ `odata.user`, доступ выдан |
| Создание номенклатуры через API | ✅ создано 3 позиции, ответ `201` |
| Создание документа поступления через API | ❌ 1С отбивает своей ошибкой «ПередЗаписью» |
| Регистр остатков «Товары на складах» | ❌ не опубликован в этой базе |
| Чтение остатков | ⏳ нужно: опубликованный регистр **или** документ поступления, созданный в интерфейсе 1С |

**Вывод:** запись справочников работает, запись документов в этой облачной базе — нет.
Остатки появятся только после того, как в базе будет документ поступления.

## 5. Что надо доделать

### Блокеры продажи (вне кода)

1. **Переезд на сервер в РФ.** Сейчас сервер в Польше — нарушение ч. 5 ст. 18 152-ФЗ.
2. **Документы по персональным данным**: договор поручения, политика, уведомление РКН,
   приказ. Шаблоны готовы в `docs/legal/`, нужно заполнить и подписать.
3. **Пароль интерфейса** — сейчас `12345678`, для показа годится, для работы нет.

### Продукт: до первого пилота

4. **Прайс реального клиента** — прогнать на 100+ позициях, получить честный процент
   спорных строк.
5. **Остатки из 1С** — либо опубликовать регистр, либо считать по документам
   (приход минус расход). Второе — час работы, есть только клиентская часть чтения.
6. **Опрос почты по клиентам.** Сейчас cron опрашивает только основную базу;
   второй клиент письма автоматически не получит. Нужны персональные IMAP-настройки
   на клиента — около часа.

### Продукт: после первого пилота

7. **Скриншоты и презентация** — автоматические снять не удалось (Playwright не
   ставится в этой среде); нужен либо ручной съём, либо одноразовая ссылка входа.
8. **E2E-проверка интерфейса в браузере** (Playwright/Chrome) — сейчас только
   дымовые тесты HTML.
9. **Шаблон КП под клиента** — логотип и цвет есть, структура под бренд — нет.
10. **Postgres вместо SQLite** и вторая точка отказа — при третьем клиенте.

## 6. Техническое состояние

| Параметр | Значение |
|---|---|
| Сервер | один VPS, Ubuntu, systemd, порт 8100 закрыт наружу |
| Доступ | HTTPS через DuckDNS, сертификат до 10.02.2027 |
| Cron | опрос почты каждые 10 мин, бэкап в 3:00 (все клиенты), очередь отправки каждые 30 мин |
| Сторож | проверка каждые 5 мин, сообщение в Telegram и MAX |
| Мультитенантность | отдельная база на клиента, реестр, панель владельца `/ui/ops` |
| PDF | Chrome на сервере (2,4 с, 55 КБ), WeasyPrint как резерв |
| Ресурсы | 981 МБ свободной памяти, 19 ГБ диска |

## 7. Риски и технический долг

| Риск | Следствие |
|---|---|
| Сервер в Польше | нельзя продавать российским юрлицам |
| Пароль `12345678` | подбирается перебором |
| SQLite, один писатель | при росте нагрузки возможны блокировки |
| Один процесс uvicorn | лимиты и кэш не разделяются при масштабировании |
| Зависимости: aitunnel, Telegram, MAX, Rambler | четыре внешние точки отказа |
| Нет e2e-тестов | регрессии вёрстки видны только глазами |

5. Демо на стенде + сводка «было 20 минут — стало 2 секунды».
