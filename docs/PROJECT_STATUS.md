# Состояние проекта kpbot

**Дата:** 26 ноября 2026
**Версия в работе:** ветка `main`, последний коммит — см. `git log -1`
**Тестов:** 315, все зелёные

---

## 1. Коротко

Сервис превращает письмо с заявкой в коммерческое предложение: разбирает позиции,
сопоставляет с прайсом, считает НДС, готовит PDF/DOCX/Excel, отправляет клиенту и
уведомляет менеджера в Telegram и MAX.

**Продукт функционально закрыт для одного пилота.** Не готов к продаже без:
переезда сервера в РФ, документов по персональным данным и одного живого клиента.

### HTTP-сервис 1С (готово 26.11.2026)

OData в Бухгалтерии на Fresh не принимает табличную часть документа, поэтому добавлен
второй путь: HTTP-сервис, который пишет счёт средствами самой 1С.

- `deploy/1c/kpbot-invoice.bsl` — готовый обработчик: JSON → «Счёт на оплату покупателю»
  с позициями, НДС, складом и проведением;
- `docs/ONE_C_HTTP_SERVICE.md` — контракт, установка, права, проверка через `curl`;
- `KPBOT_ONE_C_SERVICE_URL` и `1c-invoice --via service|auto|odata` в kpbot;
- `1c-price --apply` — цены из регистра «Цены номенклатуры» (на тестовой базе пусто);
- повторная выгрузка счёта не создаёт дубль: номер хранится в журнале решений,
  `--force` — для осознанного повтора;
- тесты клиента (успех, отказ 1С, HTTP-ошибка, отсутствие адреса) — 31 тест в `test_one_c.py`.

Осталось проверить на живой базе, где сервис опубликован: до публикации OData-путь
работает только на чтение.

### Доведение до полноты (26.11.2026)

- **Кабинет стал тенантным**: вход по ссылке `/cabinet/login?t=<код>` из `/ui/ops`,
  отдельная кука `kpbot_client_tenant`, каталог/корзина/заказы и реквизиты читаются
  из базы своего поставщика; API 1С принимает `X-Tenant`. Раньше кабинет всегда
  смотрел в основную базу — второй клиент не смог бы войти.
- **Конечный автомат статусов**: `check_transition` запрещает `sent → approved`,
  `draft_ready → sent` и мусорные значения; API отдаёт 409, интерфейс — понятное
  сообщение вместо тихой записи. Служебный повтор отправки — единственный путь с `force`.
- **Тяжёлые операции вынесены из Event Loop**: approve (DOCX/PDF), SMTP-отправка,
  запросы к 1С и чтение страниц идут через threadpool; один медленный SMTP больше
  не блокирует весь сервис.
- **Бэкап проверяется, восстановление появилось**: `backup` делает integrity_check,
  `restore --file … --yes` кладёт страховочную копию и восстанавливает базу.
- **Отчёт пилота**: `/ui/report` и `pilot-report --days 30` — заявки, доля авто-строк,
  медиана «письмо → КП», экономия времени и топ строк, требующих уточнения.
- **Срок хранения ПДн**: `purge --days 90 --yes` (или `--all`/`--tenant`) удаляет
  старые заявки, строки, журнал, очередь и файлы КП; без `--yes` — только предпросмотр.
- **Логин защищён от чужого Origin**, а `X-Forwarded-For` принимается только от
  `KPBOT_TRUSTED_PROXIES` — иначе лимит считался по IP прокси или обходился заголовком.
- **Упаковка**: `pyproject.toml`, ruff в CI (информационный этап), 315 тестов.

### Блокеры продажи (вне кода)

1. **Переезд на сервер в РФ.** Сейчас сервер в Польше — нарушение ч. 5 ст. 18 152-ФЗ.
2. **Документы по персональным данным**: договор поручения, политика, уведомление РКН,

3. **Пароль интерфейса** — сейчас `12345678`, для показа годится, для работы нет.

**Лицензия 1С.** Учебная/разработческая лицензия ограничивает число клиентов: при открытом
клиенте и веб-публикации Конфигуратор не запускается («превышено ограничение лицензии для
разработчиков»). Для записи документов и эксплуатации нужна лицензия уровня **ПРОФ/КОРП**.

### Продукт: до первого пилота

4. **Прайс реального клиента** — прогнать на 100+ позициях, получить честный процент

5. **Остатки из 1С** — либо опубликовать регистр, либо считать по документам

6. **Опрос почты по клиентам.** Сейчас cron опрашивает только основную базу;
   второй клиент письма автоматически не получит. Нужны персональные IMAP-настройки
   на клиента — около часа.

### Продукт: после первого пилота

8. **E2E-проверка интерфейса в браузере** (Playwright/Chrome) — сейчас только
   дымовые тесты HTML.
9. **Шаблон КП под клиента** — логотип и цвет есть, структура под бренд — нет.
10. **Postgres вместо SQLite** и вторая точка отказа — при третьем клиенте.
