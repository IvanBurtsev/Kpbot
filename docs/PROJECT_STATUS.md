## 1. Что это

Сервис для оптовиков и производств: письмо с заявкой превращается в готовое КП
и черновик ответа, который отправляет человек.

```
письмо .eml → позиции → матчинг с прайсом → расчёт (цена/НДС/доставка)
→ КП (HTML/DOCX/PDF) → черновик ответа → одобрение человеком → отправка
```

Ключевые принципы: цена считается только кодом по прайсу (не моделью); сомнительные
строки уходят человеку; без одобрения письмо не отправляется; деньги — `Decimal`
с округлением `HALF_UP`; у каждого клиента своя база, прайс и настройки.

## 2. Что сделано

### Ядро

- Разбор `.eml`: MIME, кодировки, `text/plain` и `text/html`, таблицы; вложения
  xlsx/docx/pdf/csv/txt (без сканов и OCR).
- Извлечение позиций правилами + LLM (OpenAI-совместимый провайдер) с откатом
  на правила, проверкой опоры на текст письма и валидацией схемы.
- Матчинг с прайсом: нормализация, словоформы, размеры, единицы, опечатки;
  объяснимый score; «не найдено» и «похоже» — человеку.
- Прайс из XLSX/CSV: колонки по смыслу, «цена без НДС» приоритетнее «с НДС»,
  необязательная колонка **«Ставка НДС»**, защита от дублей/битых строк/чужих валют.
- Расчёт: `Decimal`, построчный НДС, ставки **22/10/7/5/0 %** (в том числе разные
  ставки в одном счёте), доставка с НДС, скидка — персональной ценой клиента.
- КП: HTML (A4), DOCX, PDF (Chrome/Edge или WeasyPrint); КП с номером и датой,
  итоги сходятся с построчными суммами.
- Черновик ответа в `data/out/sent/*.eml`, отправка по SMTP только после одобрения.
- Идемпотентность по `Message-ID`: повторный polling не создаёт дубль.

### НДС и документы по закону 2026 года

- Основная ставка — **22 %** (ст. 164 НК РФ), 20/18 % в проде блокируются
  (`production_problems`), форма настроек их не сохраняет, у клиента с 20 %
  расчёт берёт 22 % и пишет ошибку в журнал.
- Разные ставки по строкам: прайс → `PriceItem.vat_rate` → `QuoteLine.vat_rate`;
  `vat_breakdown` показывает НДС по каждой ставке.
- Снимок КП хранит построчные `net`/`vat`/`vat_rate`; КП, письмо, DOCX, счёт,
  УПД, Excel и 1С используют один и тот же снимок.
- Excel «Расчёт» и «Для 1С»: цена/сумма без НДС, НДС и ставка отдельно; доставка
  строкой `DELIVERY`.
- 1С: `СтавкаНДС` по строке (`НДС22`/`НДС10`), суммы `HALF_UP`, `СуммаДокумента`
  = сумма строк; организация/склад/валюта счёта задаются настройками.

### Веб, кабинет, API

- Веб-интерфейс: входящие, карточка заявки, правка строк (подтвердить/заменить/
  количество/удалить/добавить), журнал решений, поиск/фильтр/пагинация.
- API `POST /api/v1/rfqs` с ключом; ключ клиента (`X-Tenant`), в реестре только хеш.
- Мультитенантность: отдельная база на клиента, реестр, панель владельца `/ui/ops`.
- Личный кабинет клиента: каталог с персональными ценами и остатками, корзина,
  заказы, счёт, УПД, акт сверки, роли `client_admin`/`client_manager`,
  смена/сброс пароля, письмо при смене статуса.
- Заказ из ЛК создаёт заявку поставщика с готовым расчётом; заказ помнит снимок КП
  (`quote_id`), поэтому счёт/УПД не меняются после правок заявки.
- Роли admin/manager, лимит одобрения в интерфейсе, блокировка компании обрывает
  сессии, смена пароля обрывает старые cookie.

### 1С

- OData: справочники, номенклатура, организации, склады, единицы, остатки
  (регистр или «приход − расход»), цены; пагинация `nextLink`.
- Запись номенклатуры и счёта: шапка → табличная часть → `Post()`/`Unpost()` →
  `DELETE`; откат недописанного счёта; повторная выгрузка не создаёт дубль.
- HTTP-сервис 1С (`deploy/1c/kpbot-invoice.bsl`) как резервный путь записи счёта.
- Мастер `1c-setup`, команды `1c-check`, `1c-stock`, `1c-price`, `1c-invoice`,
  `1c-order`, `1c-post`, `1c-unpost`, `1c-delete`.
- Сервер видит 1С через защищённый обратный SSH-туннель (ключ ограничен только
  `127.0.0.1:8200`, без shell); `1c-check` с сервера — 200.

### Эксплуатация

- Бэкап с ротацией и проверкой целостности, восстановление, purge старых ПДн,
  отчёт пилота, замер качества `eval`, учёт токенов и стоимости LLM.
- Сервер: Ubuntu 26.04, `/opt/kpbot`, systemd-сервис, nginx/HTTPS; на сервере
  работают таймеры: `kpbot-poll` (5 мин), `kpbot-outbox` (10 мин),
  `kpbot-backup` (03:00, keep 14), `kpbot-watchdog` (5 мин).
- Метрика «письмо → КП» считается по первой версии КП на заявку, а не по каждой
  правке; отчёт берёт последнюю версию расчёта.
- Безопасность: параметризованный SQL, autoescape, CSRF, подписанные cookie,
  rate limit, CSP/XFO/nosniff/no-store, шифрование паролей ящиков, редакция
  секретов в логах.

## 4. Что осталось сделать

### P0 — до показа клиенту / пилота

1. **Rambler IMAP:** SMTP работает, IMAP отклоняет вход. Нужен пароль приложения
   или включение IMAP в настройках ящика — без этого второй ящик не опрашивается.
2. **1С с `НДС22`:** учебная `edu2` не содержит элемента `НДС22`, поэтому живой
   счёт на 22 % в ней не создаётся. Нужна актуальная конфигурация; после неё
   счёт проверяется той же `1c-invoice`.
3. **Реальный прайс и 30 писем клиента:** текущее качество измерено на 8
   размеченных письмах и живых тестовых; нужны цифры на данных клиента.
4. **Постоянная связка с 1С:** сейчас обратный SSH-туннель с компьютера с 1С;
   для прода — 1С на сервере, VPN или туннель-служба.
5. **Ротация секретов**, попавших в переписку: root сервера, оба ящика, 1С, LLM.

### P1 — после первого пилота

6. **1С: доставка** — в счёт/заказ 1С она не выгружается (нет номенклатуры
   услуги); команда отказывает, Excel выгружает `DELIVERY`. Нужна карточка услуги.
7. **Кредитный лимит и долг** показываются, но не блокируют заказ; **API-одобрение**
   не проверяет `approval_limit` (в интерфейсе проверяет).
8. **Явная скидка процентом** — сейчас скидка реализована персональной ценой;
   отдельного поля «скидка %» нет.
9. **Мониторинг и алерты** (Prometheus/health-и, время разбора), очередь в
   Postgres/Redis при втором-третьем клиенте.
10. **152-ФЗ**: сервер за границей, нет договора поручения/уведомления РКН и
    аудита доступа к ПДн.

### P2 — техдолг

11. E2E-браузер и golden-файлы документов в CI.
12. OCR сканов — только если клиенты принесут сканы и это оплатят.
13. Шаблон КП под бренд клиента (логотип/цвет уже есть).

## 6. Риски и ограничения

1. **1С на клиентской конфигурации** (УТ/ERP) не проверялась — только учебная
   Бухгалтерия 3.0; лицензия разработчика ограничивает.
2. **Один процесс и SQLite** — rate limit и очередь в памяти; для нескольких
   воркеров нужен Redis/Postgres.
3. **Качество на «грязных» письмах** измерено на 8 примерах; правила и LLM
   покрывают не всё (количества словами — LLM).
4. **Нет биллинга, регистрации, SLA** — продажа через пилот и внедрение.
5. **Юридика ПДн** не закрыта: сервер за границей, документы не подписаны.

## 7. Ближайшие шаги

1. Включить IMAP Rambler или прислать пароль приложения.
2. Обновить 1С до конфигурации с `НДС22` (или прислать `.cf/.cfu` для проверки).
3. Прогнать прайс и 30 писем реального клиента, зафиксировать «до/после».
4. Решить, как 1С будет доступна серверу постоянно.
5. Ротировать секреты и оформить документы по ПДн.
6. После пилота: кредитный лимит, лимит одобрения в API, явная скидка,
   доставка в 1С, мониторинг.
