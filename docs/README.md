# Документация kpbot

Здесь лежит всё, что нужно знать о продукте и его состоянии. Читать в этом порядке.

| Документ | О чём | Когда читать |
|---|---|---|
| [PROJECT_STATUS.md](PROJECT_STATUS.md) | **Главный документ состояния**: что проверено на живых данных, что на демо, что доделать, риски | первым, всегда |
| [CAPABILITIES.md](CAPABILITIES.md) | Что умеет сейчас и как проверить за 10 минут | перед демонстрацией |
| [ARCHITECTURE.md](ARCHITECTURE.md) | Почему сделано так, а не иначе; границы, модель данных, безопасность | перед изменениями в коде |
| [TESTING.md](TESTING.md) | Как устроен изолированный прогон тестов | перед правками тестов |
| [ACCEPTANCE.md](ACCEPTANCE.md) | Аттестация: что и как проверено, одной командой | перед показом клиенту |
| [DEPLOY.md](DEPLOY.md) | Установка на сервер: systemd, cron, HTTPS, бэкапы | при переезде и настройке |
| [ONE_C_HTTP_SERVICE.md](ONE_C_HTTP_SERVICE.md) | HTTP-сервис 1С: контракт и установка, запись счёта с позициями | когда 1С должна принимать документы |
| [VOICE_OF_CUSTOMER.md](VOICE_OF_CUSTOMER.md) | Смоделированный голос клиента (не реальный отзыв), сценарий разговора | перед продажей |
| [legal/](legal/) | Шаблоны по персональным данным: поручение, политика, уведомление РКН, приказ | до первого клиента |
| [sales/](sales/) | Письма для первого контакта и пилотное соглашение | до первого клиента |
| [archive/](archive/) | Архив: редизайн-пакет от 25.11.2026 | не для чтения, только история |

Правило: если документ противоречит PROJECT_STATUS — верен PROJECT_STATUS.

## Перед демонстрацией или деплоем

```powershell
python scripts/doctor.py            # секреты, каналы, база, мусор в папке
```

Если менялись ключи API или пароль интерфейса — `python scripts/rotate_secrets.py`.
