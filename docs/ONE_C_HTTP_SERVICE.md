# HTTP-сервис 1С: счёт с позициями (резервный путь)

## Зачем

Основной путь записи — **OData**: шапка, затем `PATCH` табличной части, затем
`Post()`. Он проверен на живой Бухгалтерии 3.0 (см. [ACCEPTANCE_1C.md](ACCEPTANCE_1C.md)):
счёт со строками, проведение, отмена и удаление работают без изменения конфигурации.

HTTP-сервис нужен, если в конкретной базе права или состав OData запрещают прямую
запись документов, либо если бизнес-логику (проведение, печать, отправку) должен
выполнять код 1С. Документ создаёт сама 1С, kpbot только передаёт данные.
Работает и в Бухгалтерии, и в УТ/ERP.

## Контракт

```
POST https://<база>/hs/kpbot/invoice
Authorization: Basic <пользователь:пароль>
X-Kpbot-Token: <общий секрет>
Content-Type: application/json
```

`X-Kpbot-Token` — обязательный общий секрет (см. «Безопасность» ниже): без него
любой, кто знает адрес сервиса, мог бы создавать счета от имени организации.

Запрос:

```json
{
  "counterparty": "9be48252-e8f6-11f1-9a72-fa163e282ebe",
  "organization": "",
  "warehouse": "",
  "date": "2026-11-26T10:00:00",
  "comment": "",
  "lines": [
    {"sku": "EL-001", "qty": "2", "price": "100.00", "vat": 22},
    {"sku": "KR-001", "qty": "10", "price": "34.50", "vat": 22}
  ]
}
```

* `counterparty` — `Ref_Key` контрагента (обязателен);
* `organization`, `warehouse` — пусто = первая из справочника;
* `sku` — артикул из `Catalog_Номенклатура` (реквизит «Артикул»);
* `qty`, `price` — строки, чтобы не терять копейки;
* `vat` — ставка НДС в процентах для строки (0, 5, 7, 10, 20, 22). Раньше НДС
  был жёстко 20% в коде 1С — это давало неверный документ у клиентов с 10%/0%.

Ответ:

```json
{"ok": true, "number": "0000-000123", "ref": "40eef3e4-…", "error": ""}
{"ok": false, "number": "", "ref": "", "error": "Нет номенклатуры с артикулом XX-1"}
```

HTTP-код: 200 — создано, 401 — нет/неверный `X-Kpbot-Token`, 400 — битый JSON,
500 — ошибка записи в 1С. Тело ответа — те же поля `ok` и `error`.

## Установка в 1С

1. Конфигуратор → **Общие → HTTP-сервисы** → добавить сервис `kpbot`.
2. Корневой URL: `kpbot`.
3. Шаблон URL: `/invoice`, метод: `POST`.
4. Обработчик: общий модуль или модуль сервиса, функция `СоздатьСчет(Запрос)`
   из `deploy/1c/kpbot-invoice.bsl`.
5. Опубликовать базу (для Fresh — через панель публикации; для локальной —
   «Публикация на веб-сервере»).
6. Пользователю, под которым ходит kpbot, дать:
   * право на использование HTTP-сервиса;
   * чтение номенклатуры, контрагентов, организаций, складов, валют;
   * добавление и проведение документов «Счёт на оплату покупателю».
7. Проверить:

```bash
curl -u odata.user:*** -H "Content-Type: application/json" \
  -H "X-Kpbot-Token: <секрет>" \
  -d '{"counterparty":"<Ref_Key>","lines":[{"sku":"EL-001","qty":"1","price":"100","vat":22}]}' \
  https://<база>/hs/kpbot/invoice
```

## Настройка kpbot

```ini
KPBOT_ONE_C_SERVICE_URL=https://<база>/hs/kpbot/invoice
KPBOT_ONE_C_SERVICE_TOKEN=<тот же секрет, что в функции ОжидаемыйТокен()>
```

```bash
python -m kpbot.cli 1c-invoice --rfq <id> --counterparty <Ref_Key> --via service
```

`--via auto` (по умолчанию) выбирает сервис, если адрес задан, иначе OData.

## Ограничения и безопасность

- Имена реквизитов зависят от конфигурации: `СчетНаОплатуПокупателю`, `Склад`,
  `СтавкаНДС` в Бухгалтерии и УТ совпадают, но проверьте на своей базе.
- Сервис не проверяет, что цены соответствуют прайсу: это ответственность kpbot.
  В 1С попадает ровно то, что подтвердил менеджер.
- Только HTTPS и отдельный пользователь с минимальными правами.
- **Обязательно** задайте свой `X-Kpbot-Token` в `ОжидаемыйТокен()` и в
  `KPBOT_ONE_C_SERVICE_TOKEN`: иначе адрес сервиса = право создавать счета.
- В конфигурации должен присутствовать перечисление `СтавкиНДС.НДС22`
  (релизы 2026+). Для баз без него замените ветку 22% в `СтавкаНДСПоПроценту`
  на свою ставку.
- Если сервис не нужен — достаточно файла «Для 1С»: он работает всегда.
