# Личный кабинет клиента (B2B-портал)

Покупатель заходит в `/cabinet`, видит каталог с персональными ценами и остатками,
собирает корзину и отправляет заявку. Заявка попадает в очередь поставщика как
обычная RFQ с готовым расчётом — менеджер подтверждает её в привычном интерфейсе.

## Роли

| Роль | Видит |
|---|---|
| `client_admin` — директор/закупщик | всё, включая баланс, кредитный лимит, долг, акт сверки |
| `client_manager` — менеджер | каталог, корзину, свои заказы и документы; финансов нет |

Пользователей создаёт поставщик в админке: **Админка → Клиенты ЛК**. Пароль
показывается один раз при создании; компанию можно заблокировать (вход закрывается).

## Таблицы (в базе поставщика)

| Таблица | Смысл |
|---|---|
| `cabinet_companies` | компания-покупатель: название, ИНН/КПП, статус, баланс, лимит, долг |
| `cabinet_users` | пользователи ЛК: e-mail, роль, хеш пароля, мягкое удаление |
| `cabinet_prices` | персональные цены по компании и артикулу |
| `cabinet_packs` | кратность упаковки по артикулу (поставщик задаёт в демо/скрипте) |
| `cabinet_cart` | корзина пользователя: артикул и количество |
| `cabinet_orders`, `cabinet_order_lines` | заказы и строки со снимком цены |

Данные физически изолированы: у каждого клиента поставщика своя база (tenant),
а внутри базы все выборки ограничены `company_id` из сессии.

## Маршруты

| Маршрут | Назначение |
|---|---|
| `GET/POST /cabinet/login` | вход по e-mail и паролю (cookie `kpbot_client_session`) |
| `GET /cabinet/login?t=<код>` | вход в кабинет конкретного поставщика (ссылка из `/ui/ops`) |
| `GET /cabinet` | дашборд: финансы для admin, быстрые действия |
| `GET /cabinet/catalog` | каталог: поиск, персональная цена, остаток, кратность |
| `POST /cabinet/cart/add`, `/cart/qty`, `/cart/remove` | корзина |
| `POST /cabinet/orders` | оформление: проверка остатков и кратности, создание заказа и RFQ |
| `GET /cabinet/orders`, `/orders/{id}` | история и карточка заказа |
| `GET /cabinet/orders/{id}/doc/{kp\|invoice\|upd}` | документ (PDF, иначе HTML для печати) |
| `GET /cabinet/documents/act` | акт сверки (только `client_admin`) |

Ссылку на кабинет поставщик берёт в `/ui/ops` (колонка «Кабинет клиента»).
Она содержит код тенанта; после успешного входа код запоминается в отдельной
подписанной куке `kpbot_client_tenant`, поэтому админка и кабинет на одной
машине не перетирают выбранную базу.

## API-заглушки для 1С

Все требуют заголовок `X-API-Key` (ключ kpbot). Для мультитенантной установки
добавляется `X-Tenant: <код клиента>`; без него берётся текущая/основная база.

| Метод | Маршрут | Что делает |
|---|---|---|
| GET | `/cabinet/api/1c/stock` | кэш остатков |
| GET | `/cabinet/api/1c/prices` | кэш прайса |
| GET | `/cabinet/api/1c/orders` | заказы и статусы |
| POST | `/cabinet/api/1c/orders/{id}/status` | 1С сообщает новый статус |
| POST | `/cabinet/api/1c/settlements` | 1С присылает баланс, лимит, долг, статус компании |

Обмен предполагается в обе стороны: 1С отдаёт остатки/цены (или kpbot забирает
их по OData, как уже умеет), а статусы и взаиморасчёты 1С присылает сюда.

## Демо

```bash
python -m kpbot.cli cabinet-demo
# client_admin:   director@garant-stroy.example / client-admin-1
# client_manager: zakupki@garant-stroy.example / client-manager-1
```
