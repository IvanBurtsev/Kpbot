## 1. Контракт страницы: что должно быть и почему

| Функция | Зачем |
|---|---|
| Показать количество позиций и когда обновляли | менеджер должен понимать, на каких ценах он работает |
| Поиск по названию и артикулу | прайс на 10 000 позиций иначе не проверить |
| Загрузить прайс CSV/XLSX с заменой списка | прайс приходит выгрузкой из 1С или Excel |
| Колонки по смыслу, а не по номеру | у 1С «Код/Номенклатура/Единица/Цена», у шаблона «SKU/Наименование/Ед./Цена» |
| Отказ на чужую валюту | рубли из долларов никто не пересчитывает |
| Отказ на колонку «Цена с НДС» без режима «цены с НДС» | иначе НДС начислится второй раз |
| Ставка НДС по позиции (22/10/7/5/0) | в одном счёте могут быть разные ставки |
| Загрузка остатков | остаток виден в карточке заявки, нехватка подсвечивается |
| Кнопки «Цены/Остатки из 1С» | не выгружать файл руками |
| Загрузка только администратором | прайс — деньги компании, не рядового менеджера |
| CSRF, лимит размера, понятные ошибки | файл приходит извне, ошибиться легко |

## 2. Найденные дефекты

### 2.1. Загрузка смотрела на `.env`, а не на настройку клиента

**Было:** у клиента в интерфейсе включены «цены с НДС», он загружает прайс с
колонкой «Цена с НДС» — файл отклоняется с советом выставить
`KPBOT_PRICES_INCLUDE_VAT=1` в конфиге сервера. И наоборот: при включённом
`.env` и выключенной настройке клиента колонка принималась, а расчёт потом
считал цену как без НДС — документ дороже реальности на ставку.
**Стало:** и страница прайса, и мастер подключения берут режим из расчёта
клиента (`pipeline.calc().prices_include_vat`), а не из глобального конфига.
**Доказательство:** `test_vat_inclusive_upload_follows_tenant_setting`,
`test_vat_inclusive_upload_refused_without_setting`.

### 2.2. Дата обновления — сырой ISO

**Было:** «обновлён 2026-11-28T19:04:32».
**Стало:** «обновлён 28.11.2026 19:04»; то же для остатков.
**Доказательство:** `test_page_shows_human_date_money_and_vat`.

### 2.3. Цены с точкой

**Было:** `34.50 ₽`, `128.00 ₽`.
**Стало:** `34,50 ₽`, `128,00 ₽` — как в КП и карточке заявки.

### 2.4. Ставка НДС позиции не была видна

**Было:** таблица показывала код, наименование, единицу и цену. При смешанных
22/10 менеджер не видел, почему итог считается иначе, чем «цена × 22%».
**Стало:** колонка «НДС» с действующей ставкой: своя из прайса или ставка
клиента, если в файле её не было.
**Доказательство:** тот же тест + скриншоты.

### 2.5. «Показаны первые 1 из 55» при поиске

**Было:** подпись про усечение печаталась всегда, когда результат поиска
меньше всего прайса, — то есть при любом поиске.
**Стало:** «найдено N» в шапке; «показаны первые 300 из N — уточните поиск»
только когда список действительно обрезан.
**Доказательство:** `test_search_shows_found_count_not_false_truncation`,
`test_truncation_message_mentions_300`.

### 2.6. Слишком большой файл — английский текст

**Было:** `413 payload too large`, без подсказки, что делать.
**Стало:** «файл слишком большой — уменьшите размер».
**Доказательство:** `test_too_big_file_gets_russian_message`.

### 2.7. Лимит в тексте был жёстко «2 МБ»

**Было:** сообщение «файл больше 2 МБ» даже если `KPBOT_MAX_UPLOAD_BYTES`
изменён.
**Стало:** текст считает лимит из настройки (`_file_too_big()`), одинаково для
прайса, остатков, письма и мастера.

### 2.8. Замена всего прайса без подтверждения

**Было:** один клик по «Загрузить прайс» заменял весь список — ошибочный файл
стирал цены молча.
**Стало:** форма спрашивает подтверждение («Текущий список будет полностью
заменён»), как опасные действия в админке.

Дополнительно: поиск теперь не различает «ё» и «е» — «елка» находит «Ёлку».

## 3. Что проверено и работает

- **Форматы:** CSV с `;` и `,`, UTF-8/BOM/UTF-16/cp1251, XLSX, файл без шапки
  (позиционный разбор), выгрузка 1С (`Код/Номенклатура/Единица/Цена`).
- **Отказы с объяснением:** чужая валюта, шапка без цены, пустой файл, битая
  цена (строка пропускается), 20 % и 18 % в колонке ставки, неверное
  расширение, файл больше лимита.
- **Дубли артикула:** остаётся последняя строка, в журнал — предупреждение.
- **Права:** загрузку видит и делает только администратор; менеджер получает
  403 и не видит формы; без CSRF — 403.
- **Гигиена:** временные файлы после загрузки удаляются, список заменяется
  одной транзакцией, индекс прайса пересобирается по `updated_at`.
- **Остатки:** загрузка CSV/XLSX, отказ без колонки количества, дата обновления,
  показ в карточке заявки.
- **1С:** кнопки появляются только при настроенной 1С; ошибка связи
  показывается сообщением, а не 500.

## 4. Что осталось (решения, не дефекты)

1. **Пагинации нет:** показываются первые 300 позиций, дальше — поиск. Для
   10 000 позиций это работает (индекс и поиск), но «пролистать» прайс нельзя.
2. **Остатки не показаны списком** — только количество и загрузка; остаток по
   позиции виден в карточке заявки. Отдельная таблица — расширение.
3. **Экспорта прайса нет** — выгрузить текущий список файлом нельзя.
4. **1С на сервере недоступна** (туннель `:8200` не поднят) — кнопки вернут
   ошибку связи, пока интеграция не поднята.
