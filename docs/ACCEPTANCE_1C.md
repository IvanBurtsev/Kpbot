# Аттестация интеграции с локальной 1С

**Дата:** 26.11.2026
**Стенд:** 1С:Предприятие 8.3.27.2342 (x86), «Бухгалтерия предприятия (учебная)», ред. 3.0.111.25,
файловая база, Windows 10, IIS 10. kpbot — FastAPI + SQLite.
**Где:** локальная машина, публикация `http://localhost/kpbot/`.

Проверка шла **на живой базе**, без симулятора. Симулятор использовался отдельно — см. §5.
Это первая проверка OData на локальной 1С: до неё был только облачный 1С:Fresh.

## 1. Что подключили

- База восстановлена из учебного шаблона `1Cv8new.dt` (без демо-данных) в отдельный каталог,
  чтобы не трогать рабочие базы.
- На IIS создана публикация с флагом **«Публиковать стандартный интерфейс OData»**.
- Пользователи:
  - **`kpbot`** — полные права (используется для записи);
  - **`kpbot_odata`** — служебный пользователь REST-сервиса, роль «Удалённый доступ OData»,
    **только чтение** отмеченных объектов (так задумано в 1С).
- В форме «Настройка автоматического REST-сервиса» на вкладке **«Состав»** отмечены
  справочники, регистры и документы, которые сервис отдаёт. Без этой вкладки `$metadata` пустой.

## 4. Подтверждённые ограничения

1. **Счёт со строками через OData не создаётся** — 500 «внутренняя ошибка OData».
   Ошибка воспроизведена **на локальной базе**, а не только в облаке. Лечится HTTP-сервисом
   `deploy/1c/kpbot-invoice.bsl` (документ пишет сама 1С) или файлом «Для 1С».
2. **«Заказ клиента»** есть в УТ/ERP, но не в Бухгалтерии — корректный отказ `1c-order`.
3. **Лицензия разработчика ограничивает число клиентов.** При открытом клиенте 1С и
   веб-публикации Конфигуратор отказывается запускаться: «Превышено ограничение лицензии
   для разработчиков на количество клиентов информационной базы». Для эксплуатации нужна
   лицензия уровня **ПРОФ/КОРП**, учебная/разработческая для продакшена не годится.
4. **COM-соединение недоступно**: «Конфигурация не является базовой». Клиентский режим
   при этом работает — ограничение касается именно COM.
5. База пустая: нет прайса, остатков и демо-номенклатуры, поэтому чтение цен и остатков
   проверено только на симуляторе.

## 5. Симулятор 1С

`scripts/fake_1c.py` расширен до полного стенда: справочники, единицы, склады, организации,
валюты, контрагенты, регистр цен, регистр остатков, документы (GET + POST), `$metadata`.

На нём прошёл весь путь: `1c-setup` (все возможности `true`), `1c-check`,
`1c-price` (3 цены), `1c-stock` (4 строки), `1c-invoice` — **201**, `1c-order` — **201**.

Это доказывает, что клиентская часть kpbot корректна: на живой базе тот же счёт отбивает
именно 1С.

## 6. Что осталось

1. **HTTP-сервис** — добавить в конфигурацию (Конфигуратор → Общие → HTTP-сервисы →
   `kpbot` → `/invoice` → POST → `СоздатьСчет`), вставить `deploy/1c/kpbot-invoice.bsl`,
   обновить конфигурацию БД и опубликовать. Контракт — [ONE_C_HTTP_SERVICE.md](ONE_C_HTTP_SERVICE.md).
   В этом окружении шаг заблокирован лимитом лицензии разработчика; нужен 1С-специалист
   или лицензия ПРОФ/КОРП.
2. **Прайс и остатки реального клиента** — заполнить базу или подключить рабочую.
3. **Реальные письма** — 20–30 заявок, замер доли строк без правки.

## 7. Как повторить

```powershell
# живая база
python -m kpbot.cli 1c-setup --url http://localhost/kpbot --user kpbot --password ***
python -m kpbot.cli 1c-check
python -m kpbot.cli 1c-price
python -m kpbot.cli 1c-stock
python -m kpbot.cli 1c-invoice --rfq <id> --counterparty <Ref_Key>

# симулятор
python scripts/fake_1c.py --port 8200 --user kpbot --password test
set KPBOT_ONE_C_BASE_URL=http://127.0.0.1:8200
python -m kpbot.cli 1c-setup --url http://127.0.0.1:8200 --user kpbot --password test --json
```

Материалы для показа: `presentation/1c-acceptance.html` (7 слайдов, таблицы чтения/записи)
и `presentation/1c-records.txt` (Ref_Key созданных записей).

## 8. Вывод

Интеграционный слой kpbot с 1С работает: авторизация, метаданные, чтение справочников,
сопоставление артикулов, запись справочников. Единственный незакрытый пункт — запись
документа со строками: это ограничение 1С/OData, снимается HTTP-сервисом.
Для промышленной эксплуатации нужна лицензия ПРОФ/КОРП и заполненная база клиента.
