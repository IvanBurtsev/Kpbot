# Аттестация интеграции с локальной 1С

**Дата:** 26.11.2026
**Стенд:** 1С:Предприятие 8.3.27.2342 (x86), «Бухгалтерия предприятия (учебная)», ред. 3.0.111.25,
файловая база `C:\WORK\777\1c-test\edu2`, Windows 10, IIS 10. kpbot — FastAPI + SQLite.
**Публикация:** `http://localhost/kpbot/`, OData включён (`default.vrd`).

Проверка шла **на живой базе**, без симулятора. Симулятор (`scripts/fake_1c.py`) используется
отдельно для тестов клиента.

## 1. Что подключили

- База восстановлена из учебного шаблона `1Cv8new.dt` без демо-данных.
- На IIS создана публикация с флагом **«Публиковать стандартный интерфейс OData»**.
- Пользователь **`kpbot`** — полные права (чтение и запись). Пароль хранится только
  в `.env` рабочей машины, в репозиторий и логи не попадает.
- В форме «Настройка автоматического REST-сервиса» на вкладке **«Состав»** отмечены
  справочники и документы, которые сервис отдаёт. Без этой вкладки `$metadata` пустой.

## 2. Чтение

| Проверка | Результат | Детали |
|---|---|---|
| Метаданные OData | ✅ | HTTP 200, **5,3 МБ**, **1211 сущностей** |
| Справочники | ✅ | организации — 1, контрагенты — 1, склады — 1, валюты — 1, номенклатура — 1 |

| Остатки | ⚠️ | в Бухгалтерии нет регистра остатков; считаются по документам |

## 3. Запись и полный цикл документа

Проверено через OData, **без HTTP-сервиса и без изменения конфигурации**.

| Операция | HTTP | Результат |
|---|---|---|
| Создать номенклатуру | `POST Catalog_Номенклатура` | **201 Created**, `Ref_Key` |
| Изменить номенклатуру | `PATCH Catalog_Номенклатура(guid'…')` | **200**, новое `Description` |
| Удалить номенклатуру | `DELETE Catalog_Номенклатура(guid'…')` | **204 No Content** |
| Создать шапку счёта | `POST Document_СчетНаОплатуПокупателю` | **201**, `Ref_Key`, `Posted=false` |
| Записать строки | `PATCH …(guid'…')` с полным массивом `Товары` | **200**, `СуммаДокумента` пересчитана |
| Провести | `POST …(guid'…')/Post()` | **200**, `Posted=true` |
| Отменить проведение | `POST …(guid'…')/Unpost()` | **200**, `Posted=false` |
| Удалить документ | `DELETE …(guid'…')` | **204**, повторный GET — 404 |

Ключевые детали, без которых 1С отвечает 500:

1. **Шапка и строки — раздельно.** Вложенную табличную часть в `POST` платформа не принимает;
   сначала создаётся шапка, затем `PATCH` с полным массивом `Товары`.
2. В каждой строке обязателен **`LineNumber`** (строка «1», «2», …).
3. Нужны `Номенклатура_Key`, `Количество`, `Цена`, `Сумма`, `СтавкаНДС`, `СуммаНДС`.
4. Для счёта: `СуммаВключаетНДС=false`, `ДокументБезНДС=false`, `СуммаДокумента` = сумма + НДС.

### Проверенный пример

Счёт по заявке `5a906860…`: 10 × 34,50 ₽, НДС 20%.

```
Сумма без НДС: 345,00
НДС:           69,00
Итого:        414,00
```

После `PATCH` и `Post()` 1С вернула:

- `СуммаДокумента = 414`;
- строка: `Сумма=345`, `СуммаНДС=69`, `СтавкаНДС="НДС20"`;
- `Posted=true`;
- после `Unpost()` — `Posted=false`;
- после `DELETE` — `204`, документ не читается (404).

Номер документа (`Number`) присваивает 1С: `0000-000001`.

## 4. Ограничения лицензии

Согласно [официальному описанию лицензии для разработчиков](https://v8.1c.ru/platforma/litsenziya-dlya-razrabotchikov/):

- не более **3 сеансов прямого подключения**;
- не более **1 сеанса через веб-сервер**;
- не более 1 сеанса «1С:Аналитика» и 1 мобильного;
- лицензия предназначена **только для разработки и отладки**, не для реального учёта.

Поэтому:

- **OData-проверки** укладываются в один веб-сеанс, Конфигуратор не нужен;
- **нельзя одновременно** держать открытую публикацию и запускать Конфигуратор —
  появится «Превышено ограничение лицензии для разработчиков на количество клиентов»;
  перед Конфигуратором остановите пул IIS или подождите `sessionMaxAge=20` секунд;
- для эксплуатации нужна коммерческая лицензия ПРОФ/КОРП, учебная/разработческая не подходит.

## 5. Что не требует HTTP-сервиса

Прежний вывод «OData не принимает табличную часть» **опровергнут**. HTTP-сервис
`deploy/1c/kpbot-invoice.bsl` больше не обязателен для счёта; он остаётся
вариантом для конфигураций, где права/состав OData запрещают прямую запись
документов, и для серверной бизнес-логики (проведение, печать, отправка).

## 6. Симулятор 1С

`scripts/fake_1c.py` повторяет новый протокол: шапка → `PATCH` строк → `Post()` →
`Unpost()` → `DELETE`, а также CRUD номенклатуры. На нём проходят тесты без
лицензионной базы.

## 7. Как повторить

```powershell
$env:KPBOT_ONE_C_BASE_URL = "http://localhost/kpbot"
$env:KPBOT_ONE_C_USER = "kpbot"
$env:KPBOT_ONE_C_PASSWORD = "<пароль>"

python -m kpbot.cli 1c-check
python -m kpbot.cli 1c-invoice --rfq <id> --counterparty <Ref_Key> --post
python -m kpbot.cli 1c-show --ref <Ref_Key> --select "Number,Posted,СуммаДокумента,Товары"
python -m kpbot.cli 1c-unpost --ref <Ref_Key>
python -m kpbot.cli 1c-post --ref <Ref_Key>
python -m kpbot.cli 1c-delete --ref <Ref_Key> --yes
```

Для симулятора:

```powershell
python scripts/fake_1c.py --port 8200 --user kpbot --password test
$env:KPBOT_ONE_C_BASE_URL = "http://127.0.0.1:8200"
python -m kpbot.cli 1c-invoice --rfq <id> --counterparty cp1 --post
```

## 8. Вывод

Интеграционный слой работает полностью на OData: чтение справочников, создание,
изменение и удаление номенклатуры, создание счёта со строками, проведение,
отмена проведения и удаление документа. Ограничение прошлой версии было не в 1С,
а в теле запроса. Для промышленной эксплуатации по-прежнему нужны коммерческая
лицензия 1С и заполненная база клиента.
