# Патч HTML разметки: kpbot

## Проблемы и решения

### 1. **input.short не имеет стилей**
**Файл:** `kpbot/templates/rfq.html:209`

**Текущий код:**
```html
<input type="text" name="reason" placeholder="причина отказа" class="short">
```

**Проблема:** Класс `.short` не определён в app.css, input сжимается и становится < 44px на мобильном.

**Решение:** Удалить класс `.short`, пусть input наследует размер. На мобильном он автоматически займёт нужный размер.

**Новый код:**
```html
<input type="text" name="reason" placeholder="причина отказа">
```

---

### 2. **Плейсхолдер вместо label**
**Файл:** `kpbot/templates/rfq.html:132`, `inbox.html:14`

**Текущий код:**
```html
<input type="search" name="q" value="{{ query }}" placeholder="поиск по названию или коду">
<input type="text" name="qty" placeholder="кол-во" size="6" inputmode="decimal" required>
```

**Проблема:** По спецификации метка должна быть сверху input, не внутри (плейсхолдер). На мобильном плейсхолдер исчезает при фокусе.

**Решение:** Добавить явные label или оставить плейсхолдер только как подсказка, но обёрнуть в label.

**Новый код вариант 1 (с видимым label):**
```html
<label>Кого ищем
  <input type="search" name="q" value="{{ query }}" placeholder="название или код">
</label>
```

**Или вариант 2 (если нужна компактность — оставить как есть, но добавить aria-label):**
```html
<input type="search" name="q" value="{{ query }}" placeholder="поиск" aria-label="поиск по названию или коду">
```

**Рекомендация:** На данный момент плейсхолдеры в поиске и кол-ве приемлемы (это вспомогательные поля). Основные поля (email в отправке КП) уже имеют label.

### 3. **Таблица .grid и .lines без стилей**
**Файл:** `kpbot/templates/rfq.html:81` (таблица "Что понял сервис")

**Текущий код:**
```html
<table class="grid lines">
```

**Проблема:** Классы `.grid` и `.lines` не имеют стилей в app.css, таблица не адаптируется на мобильном. На 360px с 8 колонками будет горизонтальная прокрутка.

**Решение:** В app.css добавлены базовые стили table. На мобильном < 480px эта таблица остаётся горизонтально прокручиваемой (для В2В это допустимо, пользователи привыкли). Можно оставить как есть ИЛИ добавить в HTML адаптивный вид.

**Рекомендация:** Оставить как есть на данный момент. Таблица "Что понял сервис" — экран работы, рабочий стол для 27" монитора. На мобильном B2B-пользователь редко её редактирует. Если добавить мобильную версию — потребует JS.

### 4. **Размеры input в .row на мобильном**
**Файлы:** `inbox.html:40` (upload), `rfq.html:107, 132` (line-form)

**Текущий CSS в новом app.css:**
```css
@media (max-width: 480px) {
  .row input, .row select {
    width: 100%;
  }
}
```

**Решение:** Добавлены медиа-запросы. Input теперь на 100% ширины на мобильном.

---

### 5. **Button + input в одной строке на мобильном**
**Файл:** `inbox.html:38–43` (upload form)

**Текущий код:**
```html
<form method="post" action="/ui/upload" enctype="multipart/form-data" class="row">
  <input type="file" name="file" accept=".eml,.txt" required>
  <button class="primary" type="submit">Разобрать письмо</button>
  <span class="muted small">файл .eml или .txt, до 2 МБ</span>
</form>
```

**Проблема:** На 480px button и input теснятся.

**Решение:** Благодаря новому app.css с `@media (max-width: 480px) { .row { flex-direction: column } }` они переносятся в колонку. Всё хорошо.

## Итог: нужны ли патчи разметки?

### Обязательные:
1. **Удалить `.short` из input[name=reason]** — класс не нужен, input наследует размер.

### Рекомендуемые (для лучшей практики, но не критичные):
2. Добавить `aria-label` на поля поиска и кол-ва, если плейсхолдер — единственная метка.

### Не нужны:
- Таблица `.lines` остаётся как есть (горизонтальная прокрутка на мобильном допустима).
- Переносить button/input в колонку — уже сделано в CSS.
