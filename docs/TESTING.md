# Тесты

## Полный прогон

```powershell
python -m unittest discover -s tests
```

253 теста, около 49 секунд. Прогон изолирован: ни одного пакета наружу, боевой `.env`
не читается, каталог данных — свой на каждый запуск.

## Что делает стенд `tests/support.py`

Каждый тестовый модуль импортирует `support` **первым** — до любого `import kpbot`.
Стенд выставляет:

| Переменная | Значение | Зачем |
|---|---|---|
| `KPBOT_ENV_FILE` | `none` | боевой `.env` не читается: тесты не видят ключей |
| `KPBOT_OFFLINE` | `1` | реальные сетевые вызовы запрещены (см. `kpbot/net.py`) |
| `KPBOT_DATA_DIR` | `.tmp/run-<pid>-<ns>` | свой каталог на прогон, удаляется после |
| `KPBOT_LLM_ENABLED`, `KPBOT_TELEGRAM_ENABLED`, `KPBOT_MAX_ENABLED`, `KPBOT_SMTP_ENABLED` | `false` | внешние каналы выключены |
| `KPBOT_MATCH_*_THRESHOLD` | `0.75` / `0.50` | как в `.env`: результат не зависит от настроек окружения |

Сетевой замок подменяет транспорт `httpx` и точки подключения `smtplib`/`imaplib`.
Тесты, которым нужен «успешный» ответ, передают `httpx.MockTransport` — он не использует
`HTTPTransport` и под запрет не попадает. Локальные адреса (`127.0.0.1`) разрешены:
тест почты поднимает собственный SMTP-приёмник.

## Отладка

```powershell
# сохранить каталог прогона (по умолчанию он удаляется)
$env:KPBOT_TESTS_KEEP = "1"; python -m unittest discover -s tests

# один модуль
python -m unittest discover -s tests -p "test_api.py"
```

Раньше в `.tmp` копились заявки и выученные пары, и повторный прогон падал не из-за кода.
Теперь каждый запуск получает чистый каталог, поэтому чистить `.tmp` вручную не нужно.

## Почему это важно

До изоляции `python -m unittest` читал боевой `.env` и в одном прогоне отправлял
32 настоящих сообщения в Telegram и 29 запросов в LLM, а при повторном запуске
давал 8 падений. Сейчас любой такой вызов — ошибка `ConnectError` с текстом
«сеть запрещена в тестах».
